Fifth beta of DCS VoiceCom: offline voice control for DCS World. This release makes voice-line slots typed by name, accepts spoken text like "TGT 2", fixes radios whose controls were saved with the wrong letter case, and rebuilds the Enter value window around the cockpit display: you pick the digits on the display instead of typing places and read-back outputs.

> **Beta.** The ARC-210 fix and the search fields were tested in DCS with the A-10C II. The new Enter value window was tested under Wine with a simulated F-14 UHF radio, not yet in DCS. Other parts still have little testing against a live DCS session. Please report what you find in Issues.

## Install

1. Install [DCS-BIOS (Skunkworks)](https://github.com/DCS-Skunkworks/dcs-bios) in DCS, if you don't have it yet.
2. Download `DcsVoiceCom-Setup-0.1.0-beta.5.exe` below and run it. It installs over earlier betas; your settings and profiles are kept.
3. Start DCS VoiceCom, open **Settings**, set **Push-to-talk → Rebind** and your **Microphone**, then save.
4. **Check your voice lines** for slots that need a new name (see the breaking change below).

Windows may show a SmartScreen warning because the installer isn't code-signed yet. Choose **More info → Run anyway**.

## ⚠️ Breaking change: slot types

The name of a slot now sets its type. A slot with any other name needs a type after a colon.

| Write | Type | Example |
|---|---|---|
| `{number}` | whole number | "seventy three" → `73` |
| `{freq}` | number with decimals | "two five five decimal eight" → `255.8` |
| `{text}` | words joined without spaces | "TGT 2" → `TGT2` |
| `{alt:number}`, `{com2:freq}`, `{wp:text}` | the same types, for two slots of one kind in a phrase | |

Ranges (`{channel:1-20}`) and options (`{band:X|Y}`) work as before.

**What to change in your profiles:** a slot such as `{num}` or `{chan}` is now reported as a problem and its phrase is left out. Rename it to `{freq}`, `{number}` or `{text}`, or add a type (`{num:freq}`). Remember to rename it in the command's steps too (e.g. an Enter value step's value `{num}` → `{freq}`).

## What's new

- **`{text}` takes words as heard:** "TGT 2", "TGT2" and "tango golf tango two" all give `TGT2`. Before, only spelled NATO letters worked.
- **Control names are sent with the exact DCS-BIOS spelling.** DCS-BIOS is case-sensitive, so a control saved as `ARC210_100kHZ_SEL` (instead of `ARC210_100KHZ_SEL`) did nothing. This fixes the A-10C II ARC-210 100 kHz wheel.
- **Display check finds the value among other text.** The A-10C CDU line `NN552~      ` now passes for `NN552`. Part of a longer word or number doesn't count.
- Control, display and key fields are searchable: type `arc 100k` to find `ARC210_100KHZ_SEL`, then click it or pick it with ↑/↓ and Enter. The arrow shows the full list. Unknown control names are listed as problems; known ones are corrected to the right case.
- **Built on .NET 10** (was .NET 8, whose support ends in November 2026). Nothing to install: the installer still brings its own .NET. To build from source you now need the .NET 10 SDK.

## Enter value: pick the fields on the display

- **Choose the display** that shows the value (e.g. `PLT_UHF_DISP`). Its characters show as cells. Click a character, Shift+click to widen, and make it a **Wheel**, the **Keypad** field or **Read-only** text. Place and width come from where the field sits; *Scale* is gone.
- **One display for everything.** Every wheel is read back from its own characters of that display, and the same display is checked at the end.
- **Range per wheel**, in click order: `0-9`, `22-39`, or a list like `X,Y` (TACAN band) or `00,25,50,75` (25 kHz wheel).
- **Switches / dials or keypad**, never both in one step. A keypad step types into one field, with the text on the left or right. It never clears the field on its own; add a CLR press as a step when needed. For latitude, then longitude, use two steps.
- **Try a spoken value** shows in green which characters will change, and the selected wheel's clicks (`'1' → '3' · 2 clicks up`).
- **Fill from radio…** places the radio's wheels on the live display.
- **Displays without a decimal point** (`2513` for 251.3): set *Implied decimals* under Advanced.
- A value the display can't show (too long, outside a wheel's range, more decimals than the display) is refused before anything is sent.
- **F-14 sample profile:** the UHF frequency command now reads all wheels from `PLT_UHF_DISP`.

### Older Enter value steps

- Enter value steps from earlier betas keep working as they are.
- When you open one in the window, a wheels step is converted to the new layout using what the display shows at that moment. **Check the fields before saving**: if the radio is in another mode (a preset step opened while the radio shows a frequency), they land on the wrong characters. Without DCS the layout is guessed.
- A keypad step stays as it is until you pick its field on the live display. Its *before*/*after* keys keep working, but are no longer edited in the window.

## Known limits

- **Setting up Enter value fields needs DCS running**, so the window can see where each digit is. Without DCS it shows a warning and empty cells; control, range, mode and keys can still be edited.
- The F-14 UHF preset command is still in the old format.
- A `{text}` slot takes any word, so a misheard word is typed as well. The display check catches it.
- Windows 10/11 x64 only.
- Installer is not code-signed.
